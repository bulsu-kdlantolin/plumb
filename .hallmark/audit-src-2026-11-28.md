# Hallmark audit: `src/`

**Date:** 2026-11-28  
**Scope:** `src/` and its Vite app at `/`  
**Design authority:** `DESIGN.md` map to `.impeccable/design-full.md`, plus the current `AGENTS.md` rules  
**Audit mode:** read-only. No application source files changed.

## Pre-flight

Plumb is a local-first planning workbench for developers, with a four-step architecture pipeline, canvas views, compiler output, local persistence, and context-bundle export. It already has a blank-plan path with an optional PulseBoard example. Preserve the product structure, Rust/soot token direction, and working flows. This audit introduces no design or implementation changes.

The Vite app rendered in Chromium after routing browser traffic only to localhost. Google Fonts could not be reached in this environment, so the captures use fallback faces. Hallmark marks this as a fallback and explicitly prevents typography sign-off. Geometry, overflow, and field-edge checks did run. I additionally inspected dark and light workbench states and opened the compiler panel using an isolated browser profile.

## Final mechanical results

Hallmark static plus render pass: **57 FAIL, 171 REFLEX, 9 WARN** across 26 source files and one rendered route. The static pass accounts for 54 FAIL and 170 REFLEX; rendered checks add viewport overflow, one field-edge contrast failure, and one small-text Reflex.

### Floor findings

- **Horizontal overflow (34, 8 findings):** `src/index.css:85,134,147,599,610,643` declares `overflow-x: hidden` and `100vw`-based widths. The render tier measured the start screen at **939px on a 768px viewport** and **1094px on a 1024px viewport**. In a separate workbench capture with the compiler open, the document also measured **1299px at 1024px and 1280px**. The mobile viewport did not gain document-width overflow, but action controls collapse to icons.
- **Field-edge contrast (40):** at 1440px the rendered dark-theme text input and textarea edges measured **1.66:1**, below Hallmark’s 3:1 non-text threshold. The static pass also flags the custom checkbox at 1.00:1 (`src/index.css:101,362`). The separate light-theme screenshot looked legible, but it does not clear the measured dark-theme defect.
- **Disabled control state (39a):** `src/index.css:332` disables the custom select trigger with opacity alone; the disabled state needs distinct fill, ink, cursor, and native disabled behavior.
- **Un-tokenized values (48, 26 findings):** `src/index.css:272,738-767` retains a raw shadow color and shadcn OKLCH values outside the semantic token block.
- **Copy tells (19, 4 findings):** `src/components/canvas/DesignPreviewCard.tsx:34,42`, `src/components/pipeline/Step3DataApiForm.tsx:15`, and `src/components/pipeline/Step4DesignForm.tsx:16` include generic “Acme” sample copy and/or em dashes.
- **Eyebrows (54, 2 findings):** `src/components/layout/LeftRail.tsx:15` and `src/components/layout/ProjectStart.tsx:41` add inert labels immediately before headings.
- **Template punctuation (63, 4 findings):** attached arrows and middle-dot metadata appear in `src/components/layout/CenterCanvas.tsx:176`, `src/components/layout/RightCompiler.tsx:112`, `src/components/pipeline/Step4DesignForm.tsx:23`, and `src/components/ui/ProjectSwitcher.tsx:30`.
- **Tracked uppercase labels (67, 11 findings):** `src/index.css:145,148,183,259,316-322,577,596,616` styles labels and menu metadata as tracked uppercase text.

### Reflex findings

- **Spacing scale (24b, 158 findings):** off-scale gaps and padding values are spread throughout `src/index.css`. Tackle these as a token pass rather than individual exceptions.
- **Font families (37, 1 finding):** `src/index.css:1-8,626,724-726` pulls in Space Grotesk, IBM Plex Sans, JetBrains Mono, and Geist Variable.
- **Monospace label voice (64, 11 findings):** labels and small metadata use mono outside code and numeric contexts; examples include `src/index.css:183,233,253,317`.
- **Small running text (75, 1 render finding):** three 10px labels at 1440px were flagged as hard to read.

### Finish and render warnings

- `src/index.css:394`: empty-state prose measure is 36ch.
- `src/index.css:210`: no balanced display-heading rule was found.
- `src/index.css:97`: one control-container recipe is reused across 25 selectors.
- `src/index.css:272`: `.shortcut-dialog` combines a hairline with a wide soft shadow.
- **F18 touch target:** a button measured 38×44px on the phone and 109×30px at 1440px.
- **Fallback typography:** external `fonts.googleapis.com` did not load. Typography cannot be signed off from these captures.

## Render observations

Hallmark captured 1280×800, 1440×900, and 1920×1080 folds plus 1440px and 375px full-page views in `.hallmark/before/`. The initial screen communicates blank-plan creation and clearly marks the example as optional. At phone width the pipeline, editor, and compiler stack vertically; this avoids horizontal page overflow but makes the handoff a long scroll. The create action loses its visible text at phone width and renders as a narrow icon control.

My isolated workbench captures are in `.hallmark/shots/`: the dark and light surfaces remain distinct, and the compiler body text is readable in light mode with fallback fonts. Opening the compiler exposes a width failure around tablet and compact desktop sizes. The captured light state does not negate the measured dark input-edge failure.

## Recommendation

The lightest sufficient depth is **polish**, not a full redesign. Keep the current planning and export flows. Resolve overflow, field contrast, checkbox contrast, disabled styling, and mobile action clarity first; then consolidate spacing, type, labels, and token usage. Repeat the visual audit with Google Fonts reachable before signing off typography.

## Limits

No visual score is reported. Hallmark’s geometry and contrast render checks ran, but the intended font faces were unavailable; typography and final visual craft are not signed off. No build or test command was run as part of this audit.
